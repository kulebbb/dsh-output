现状

当前实现的样子：三行控件都在抢注意力，还没看到内容就先累了。

当前实现
文件产出物 2Git 提交图×
  • 数字跟着每个类型跑：五个标签各带一个计数，4px 间距把它们黏成「全部2 文档2 表格0 图片0 其它0」一句连读，扫不出「哪里可以点」。
  • 三个 0 是纯噪声：这次会话根本没有表格/图片/其它，却各占一个可点区域。
  • 选中态太弱：只有一层几乎看不见的浅底，深浅主题下都靠猜。
  • 两行控件堆叠：头部 38px + 控件区 72px，第一个文件落在面板顶部 110px 处；而这 72px 里的信息量只有「5 个标签 + 1 个输入框」。
  • 搜索框常驻：只有 2 个文件时它也在，一个没有用武之地的输入框却占了最贵的一行。

三个方向

三个方向都解决「黏成一句」和「0 值噪声」，差别在保留多少信息、以及省下多少高度。

宽度可切换 · 深浅可切换
方向 A · 分段式类型推荐
文件产出物 2Git 提交图×
  • 类型收进一条浅底分段槽，选中项浮起来，一眼看出「这是一组单选」。
  • 计数为 0 的类型自动退场；2 个文档时只剩「全部 / 文档」两段，干净。
  • 筛选与搜索间隔 12px，搜索框略降一档视觉权重，主次分开。
  • 类型达到 3 种以上时行内会变长（已有横向滚动兜底）。
适合：绝大多数会话只有 1–2 种类型，这条改动去掉的正是噪声，改动量也最小。
方向 B · 单行工具条
文件产出物 2Git 提交图×
  • 类型选择收进「全部 ▾」下拉，和搜索框并成一行，直接省下一整行。
  • 下拉里保留全部类型与计数，0 项置灰但仍列出来——层级更清楚。
  • 不点开就看不到有哪些类型，也多一次点击。
  • 要自绘浮层 + 键盘可达性（多约 60 行代码，风险高于 A）。
适合：右栏常被拖得很窄（320 及以下），高度比信息可见性更值钱的时候。
方向 C · 图标分段 + 搜索入头
文件产出物 2Git 提交图×
  • 类型只留图标（计数进 tooltip、0 项直接禁用变灰），控件区压到一行 39px，列表第一屏多出近两行内容。
  • 搜索收进头部放大镜，点开才展开——2 个文件时它不再占位。
  • 图标含义要猜（「三层横线」= 全部），新用户靠 tooltip 才能确认。
  • 搜索变成两步操作，常用搜索的人会觉得变慢。
适合：你几乎总是拖到 320px 用、并且很少搜索的情况；否则不划算。

怎么选

高度只是表象：右栏通常 800px 以上高，缺的不是高度，是「一眼看懂哪儿能点」。

方案 控件区高度 类型可见性 搜索 改动量 / 风险 我的判断
现状 72px（+38 头部） 5 个类型全显示，含 3 个 0 噪声 常驻一行 — 五个数字黏成一句连读，选中态几乎看不见。
方向 A 推荐 84px 只显示有内容的类型，分段槽 清晰 常驻一行 CSS + 1 处渲染过滤
约 30 行		 噪声清零、选中态明确，类型始终可见；代价是高度反而多 12px——但右栏不缺这 12px。
方向 B 46px 点开下拉才看到 多一次点击 常驻一行 需自绘浮层 + 键盘可达
约 60–90 行 较高		 最省高度；但你右栏高、文件少，省下的高度换不回一次多余点击。
方向 C 39px 图标 + tooltip 要猜 点放大镜才展开 约 50 行 中 最紧凑，也最容易让第一次用的人不知道那排图标是筛选。
推荐：方向 A 当前实现的问题本质是信息噪声（5 个标签 + 3 个 0）和选中态太弱，不是高度不够。 A 用最小的改动同时解决这两点，并且让类型始终可见；B/C 省下的高度在这个面板里没有收益。 如果更想要「极简一行」，B 也可以做，代价是要多写一套浮层交互（键盘方向键、Esc、点外部关闭）， 这部分需要额外测一轮。
需要确认的两件事
  1. 选哪个方向（推荐 A；若在意「单行」，选 B）。
  2. 0 计数的类型要不要藏：A 默认藏起来（只剩有内容的类型 + 「全部」）；如果希望类型行永远固定五项、位置不跳动，可以改成保留但置灰不可点。
